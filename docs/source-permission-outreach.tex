\textbf{Use:} asking organizers for written permission to index public listings\\
\textbf{Not:} a partnership announcement, a scraper backlog, or a promise that any feed will go live\\
\textbf{Product:} Causey (\url{https://causey.dev})\\
\textbf{Related:} \texttt{ingestion/README.md}, \texttt{lib/ingestion-sources.ts}, \texttt{lib/category-discovery.ts}

\vspace{0.35em}
\hrule
\vspace{0.85em}

Use this when asking organizers for written permission to index their public listings on Causey. Chess search is already usable (US Chess TLA and related feeds). Debate, STEM, arts, and writing stay thin until the bodies below say yes---or until a first-party page is clearly allowed without a license (see ``Confirm before building,'' not the blocked list).

Do not scrape a blocked source while an email is in flight. A verbal ``sounds fine'' is not enough to turn automation on.

\section*{What we ask to index}

Only \textbf{factual listing metadata}, with a link back to the official page:

\begin{itemize}
  \item Event or program name
  \item Official canonical URL
  \item Published dates / status (open, closed, tentative)
  \item Category and published format (for example Public Forum, Division~C)
  \item Online vs in-person, and published city/state or ``online''
  \item Eligibility and fee \textbf{only if the public page already states them}
\end{itemize}

We do \textbf{not} ask for, and will not take:

\begin{itemize}
  \item Logins, membership-only calendars, or behind-the-wall PDFs
  \item Ballots, pairings, speaker points, contest problems, solutions, or results dumps
  \item Student, coach, or judge personal data
  \item Logos or marks (attribution is a text name + link unless brand use is granted separately)
  \item Registration checkout, payment, or tab-room software features
  \item Cloudflare or other access-control bypasses
  \item Implied endorsement (``official Causey partner of \ldots'')
\end{itemize}

Cadence if they say yes: polite, sequential fetches (about twice weekly), identifiable user agent, fail closed if the page changes or robots/terms later forbid it.

\section*{What written permission must say}

Keep the reply as email or a signed note. Engineering will not flip a kill switch on a hallway conversation.

A usable yes includes:

\begin{enumerate}
  \item \textbf{Who} is granting it (organization name, person's role, date).
  \item \textbf{What} we may copy: public tournament/program listings (name, dates, location or online, eligibility/fees if published, official URL).
  \item \textbf{Where} we may show it: Causey's website and iOS/Android apps, including search and family/org views.
  \item \textbf{That} automated fetching of those public pages (or a named API) is allowed for that purpose.
  \item \textbf{Commercial / public reuse} if their terms currently ban it (NSDA/Tabroom especially).
  \item \textbf{What is out of scope} if they care: no participant PII, no problems, no logos unless separately granted.
  \item \textbf{Revocation}: they can withdraw; we stop the feed and unpublish those rows.
\end{enumerate}

Store the file off-git (email archive). In product, record the date in
\texttt{lib/ingestion-sources.ts} field \texttt{permissionReviewedOn} and only then
enable the adapter or env gate. Tabroom already uses
\texttt{TABROOM\_WRITTEN\_PERMISSION=1}.

\section*{Short email you can send}

\noindent\textbf{Subject:} Permission to list public [Tabroom / MATHCOUNTS / \ldots] events on Causey

\begin{displayquote}
Hello,

Causey (\url{https://causey.dev}) is a student competition discovery app. Chess listings are the furthest along; we are careful about other sources and do not scrape sites that forbid automation or public reuse.

We would like written permission to fetch your \textbf{public} [tournament calendar / competition search / event API] and display factual listing information for students, families, coaches, and schools: event name, dates, location or online, eligibility and fees only when you already publish them, and a link to your official page. We would not collect participant data, contest content, or ballots, and we would not use your logo unless you grant that separately.

Fetching would be polite and infrequent (on the order of twice a week), with an identifiable user agent. You could revoke permission and we would stop the feed.

If this is in scope, a short email from someone who can grant it---plus any attribution or trademark rules---is enough for us to keep on file. Happy to jump on a call.

Thank you,\\
{[Name]}\\
Causey
\end{displayquote}

Customize the bracketed source. For FIRST, say \textbf{API token for event listings}, not HTML scrape. For VEX, say \textbf{ordinary access or an official listings API}, not a Cloudflare workaround.

\section*{After a yes}

\begin{enumerate}
  \item File the letter off-git; note date and grantor here and in \texttt{permissionReviewedOn}.
  \item Re-check \texttt{robots.txt} and current terms the same week (landscapes shift).
  \item Scope the adapter like existing non-chess feeds: official HTML or named API only, exact dates or no row, no invented regionals, no third-party registration hosts.
  \item Enable the existing env/admin gate only for that source (Tabroom:
        \texttt{TABROOM\_WRITTEN\_PERMISSION=1} plus restoring dispatch).
        Do not treat one org's yes as permission for another.
  \item Keep site-wide product copy honest: still incomplete coverage, confirm with the organizer.
\end{enumerate}
